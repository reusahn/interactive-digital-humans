## Metric-definition clarification

Two locality scales had initially been mixed together for the ankle probe.

Strict ankle/foot diagnostic:

```text
left_ankle + left_foot
```

Coarse semantic region:

```text
left_hip + left_knee + left_ankle + left_foot
```

Thus the baseline ankle-z value of **26.57%** is a fine joint-local diagnostic and counts propagation into knee/hip as outside. Under the full-left-leg target, the same +10° perturbation falls to **5.380455%**, and to **3.126863%** after dominant-joint confidence >= 0.9 filtering. The -10° result is nearly identical.

This supports a hierarchical interpretation rather than a single binary leakage number.

## Step 10 — Signed and magnitude response

The left-wrist z sweep at ±5°, ±10°, ±20°, and ±30° is approximately linear and sign-symmetric.

High-confidence outside displacement scales from about **5.083** at ±5° to about **30.15** at ±30°, while the high-confidence outside ratio remains near **12.26%**.

The HUGS-to-SMPL gap survives both sign changes and a six-fold variation in perturbation magnitude.

The defensible statement is therefore that, under this Seattle/frame-0 wrist-z diagnostic, the HUGS Gaussian deformation pipeline exhibits a stable amplification of normalized nonlocal and especially contralateral-arm displacement relative to an SMPL-only vertex control.

This is evidence of amplification, not yet proof of a representation failure.

### High-confidence contralateral subset

- Gaussian count = **33,072**

The K=6 target therefore does **not** explain the observed cross-body motion through accidental direct left-wrist support on right-arm Gaussians.

### Important exact-config correction

The packaged Seattle `config_train.yaml` does **not** use the current source-tree name previously assumed in the notes. It reports:

```text
mode: human_scene
human.name: hugs_triplane
human.use_deformer: true
human.disable_posedirs: true
human.n_subdivision: 2
human.triplane_res: 256
human.canon_pose_type: da_pose
human.optim_betas: false
human.optim_pose: true
human.optim_trans: true
human.loss.lbs_w: 1000.0
```

The saved checkpoint contains:

- three triplane tensors of shape **1 × 32 × 256 × 256**,
- deformation-decoder state with **48,664 parameters**,
- final skinning output with **24 channels**.

The current HUGS source tree no longer contains a `hugs_triplane.py` model file, while the checkpoint tensor structure matches the current triplane/deformation-decoder architecture closely. Therefore the next learned-weight export should reconstruct the triplane and deformation decoder **directly from the checkpoint state**, rather than depend on current trainer name aliases.

Because `use_deformer: true`, the actual Gaussian deformation path uses learned LBS weights. The Step 13A K=6 weights are a regularization/support target rather than the learned weights themselves.

## Next question

Do the actual **learned per-Gaussian LBS weights** explain the stable contralateral wrist response?

Next test:

1. reconstruct triplane feature sampling directly from the checkpoint,
2. reconstruct the deformation decoder from its saved state,
3. reproduce the decoder's softmax LBS activation for all 472,958 Gaussians,
4. compare learned LBS against the Step 13A K=6 target,
5. focus on the 33,072 high-confidence contralateral Gaussians and the high-displacement nonlocal subset.

If learned right-arm Gaussians carry anomalous left-wrist / left-hand influence, that is a direct candidate mechanism for the cross-body amplification. If their learned wrist influence is also negligible, move downstream to the learned transform construction itself.
