# Research Session Checkpoint - 2026-09-16 Step 18B1C-R

## Purpose

Resolve the Step-18B1 elbow regression blocker by isolating the manual SMPL transform implementation from `smplx==0.1.28` and testing source-exact chunked versus one-shot CPU LBS evaluation against the frozen Step-17B1 frame-2 displacement arrays.

This audit remained elbow-only. No shoulder causal computation was performed and no frozen tolerance was changed.

## Main result

The manual Step-18 transform construction is bitwise identical to the source-exact SMPLX transform construction for all three checkpoints, both before and after the elbow perturbation.

```text
Seattle manual A == smplx A: True
Parkinglot manual A == smplx A: True
Jogging manual A == smplx A: True
manual A bitwise exact vs smplx in all checkpoints: True
```

Chunked and one-shot CPU LBS evaluation are also effectively identical. Parkinglot/Jogging are bitwise exact between chunked and one-shot for both learned and K6 conditions. Seattle differs only by negligible floating-point noise in learned displacement (`mean abs ~1.35e-14`, `max abs ~6.37e-9`).

## Frozen aggregate regression gate

The source-exact CPU path still reproduces only 3/6 learned/K6 aggregate tests at the frozen `1e-5` contralateral-sum tolerance. All K6 conditions pass. All learned conditions remain just outside tolerance.

Per-Gaussian learned agreement remains extremely high:

Mean per-Gaussian absolute learned differences remain around `5e-8` to `9e-8`.

## Interpretation

Two hypotheses are now ruled out as explanations for the remaining Step-18B1 historical mismatch:

1. manual SMPL transform construction versus official `smplx.lbs`
2. chunked versus one-shot CPU skinning

The remaining discrepancy is a tiny distributed floating-point/backend provenance difference. Because the archived Step-17 learned fields were generated in an earlier runtime and dense learned LBS weights accumulate many more floating-point operations than sparse K6 weights, the next audit should determine whether the historical arrays were produced on CUDA and whether a CUDA float32 recreation matches the archived learned arrays more closely.

Do not widen the frozen `1e-5` tolerance after seeing this result.
