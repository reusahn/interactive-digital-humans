Test whether the official released HUGS legacy software stack recovers the frozen Step-17B1 elbow frame-2 displacement arrays before any shoulder computation.

## Comparison with current CUDA stack

Current A100 + PyTorch 2.11.0 + CUDA 12.8 strict-FP32 Parkinglot learned error was approximately `+1.1049e-04`.

Legacy A100 + PyTorch 1.13.1 + CUDA 11.7 changes the Parkinglot learned error to approximately `-2.8672e-05`, substantially closer to the frozen archive but still outside the fixed `1e-5` regression gate.

This demonstrates that CUDA/PyTorch software environment materially changes the tiny aggregate mismatch, while the scientific displacement field remains effectively unchanged.

## Interpretation

The official HUGS software stack alone is insufficient to reproduce the historical Step-17B1 archive exactly on the current A100 hardware. The remaining blocker is therefore no longer explainable by CPU/CUDA selection, SMPLX implementation, tensor rank, norm placement, TF32, or software-stack version alone.

The strongest remaining numerical provenance candidate is GPU architecture / low-level CUDA kernel selection. The historical Step-17 log establishes CUDA execution but does not identify the GPU model. A second GPU architecture should be tested before any change to the frozen regression policy.

No shoulder computation ran and no tolerance changed.
